# Security policy

Do not post vulnerabilities, keys, resumes or call exports in public issues.
Use GitHub's **Security > Report a vulnerability** when private reporting is
enabled. If unavailable, ask only for a private contact method in a public issue;
do not include exploit details.

Report the version, prerequisites, impact and a minimal reproduction using
fictional data. Do not test against another operator's live service or accounts.
No guaranteed response time or bug bounty is offered.

Keep provider/payment/email keys private. Rotate compromised credentials;
deleting a file from Git does not revoke a key. Builds may be unsigned. Verify
release sources and checksums before running them.
